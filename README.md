# Saratov Administration

## Взаимодействие с проектом

Сели за новую задачу, получили последние изменения из удаленного репозитория. Первым делом синхронизируем зависимости:
```bash
npm i
```
```bash
composer i
```
После чего выполняем сборку фронтенда:
```bash
npm run build
```

---
Затем выполняем миграции базы данных:
```bash
php artisan migrate
```
---
В случае ошибки на текущем этапе (или в момент захода на какую либо страницу сайта) можно попробовать запустить миграции с чистого листа, **предварительно полностью очистив базу данных**:
```bash
php artisan migrate:fresh
```
---
После очистки базы данных можно воспользоваться функцией заполнения тестовыми даннымы:
```bash
php artisan db:seed
```
Эта команда выполнит код в т.н. сидерах (seeders), которые лежат в `database/seeders`, на текущий момент команда:
- Создаст пользователя для админ-панели с логином `admin` и паролем `12345678`
- Создаст тестовые сущности для моделей Restaurant (заведения) и GuidedTour (экскурсоводы) в кол-ве 8 штук на каждую (без фотографий)

Если после создания тестовых сущностей оказывается, что они содержат контент не на русском языке, то необходимо изменить локаль в приложении. Для этого следует заменить строчки в файле .env следующим образом:
```env
APP_LOCALE=ru
APP_FALLBACK_LOCALE=en
APP_FAKER_LOCALE=ru_RU
```
После чего снова выполнить команды `php artisan migrate:fresh` и `php artisan db:seed`

---
Для развертывания приложения следует запустить команду:
```bash
php artisan serve
```
Эта команда запустит сервер PHP и позволит видеть изменения в файлах `.php` и `.blade.php` без перезапуска.
Однако для того, чтобы применить изменения в файлах `.css` и `.js` (`resources/css/*` и `resources/js/*`) необходимо после изменений в этих файлах выполнять пересборку фронтенда командой `npm run build`. 
Это можно делать вручную, однако теперь присутствует отдельная команда, позволяющая автоматически следить за изменениями в `resources/css/` и `resources/js/` и выполнять пересборку фронтенда. Для этого необходимо запустить (в отдельном терминале) команду `npm run build:watch`.

---
Иногда приложение может вести себя странно, страницы могут не изменяться внешне или не изменять поведение после фактического изменения верстки, стилей, кода и пересборки фронтенда. Причиной этому может быть попадание некоторых фрагментов приложения в кэш. Для полной очистки кэша приложения может быть использована команда:
```bash
php artisan optimize:clear
```
Другим вариантом исправления может послужить перезапуск сервера для разработки (`ctrl + c` → `php artisan serve`)

---
Для доступа в админ панель следует воспользоваться маршрутом `/admin/login`
Если в админ панели вместо прикрепленного изображения присутствует индикатор его отсутствия, то необходимо убедиться в том, что переменная `APP_URL` в файле .env соответствует фактическому url развернутого приложения, включая номер порта:
```env
APP_URL=http://localhost:8000
```

Фактический номер порта отображается в терминале при запуске приложения с помощью `php artisan serve`.

Для доступа к отладочной информации приложения следует воспользоваться маршрутом `/telescope` (необходимо предваритально произвести вход в админ панель)
